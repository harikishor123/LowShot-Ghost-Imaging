How the U-Net was trained, validated and tested

MedMNIST microscopy extension (blood smears + H&E tissue) and its Poisson-noise version. Every statement below was checked against the project code, the frozen training reports, freeze records and result CSVs. The onion study used the same procedure on its own split (341 / 75 / 74 images).

1 · Dataset10,000 images from the official MedMNIST splits
2 · Train7,000 training images, 32 measurement sequences each
3 · Validate each epoch1,000 validation images × 3 sequences
4 · Select + freezelowest validation MSE → best.pt, MD5 recorded
5 · Test once2,000 test images × 4 sequences

1. Training data

The U-Net was trained on the 7,000 train images only: 3,500 BloodMNIST + 3,500 PathMNIST.

  • Source split: data/extension_medmnist/processed/objects_64.npz (field split), drawn from MedMNIST's official train split. Counts in the file: train 3,500 + 3,500, validation 500 + 500, test 1,000 + 1,000.
  • Training code takes only split == "train": ext_train.py:76, ext_poisson_train.py:70. The training pool pool/pool_train*.npy holds exactly those 7,000 IDs (pool_meta.json: 7,000 IDs, all prefixed …_train_…).
  • Each training image has 32 simulated measurement sequences; each epoch uses one of them per image (ext_poisson_train.py:100), so the network sees 7,000 input–target pairs per epoch.
  • Input = DGI image from N shots; target = the original clean image (ext_poisson_train.py:74–75). Loss MSE, Adam 1 × 10⁻⁴, batch 16, at most 80 epochs.
  • Every one of the 20 training reports records n_train_images = 7000, realisations_per_image = 32.

2. Validation during training

Yes: a separate validation set was scored after every epoch.

  • Validation (selection) set: all 1,000 validation images (500 + 500) × 3 measurement sequences (seeds 2040–2042) = 3,000 pairs. Recorded as selection_pairs = 3000 in every training report; stored in pool/selection_val.npz (1,000 IDs, all …_val_…).
  • Scored after each epoch: ext_poisson_train.py:121 (ev = sel_eval(model)), likewise ext_train.py:134. The per-epoch values are in each model's history.csv (columns val_loss, val_psnr, val_ssim, val_correlation; for example, 81 rows = epoch 0 + 80 epochs for p10 / 1,000 shots).

3. Model selection

The checkpoint with the lowest validation MSE (validation loss) was kept as best.pt. PSNR, SSIM and correlation were logged but not used for selection.

  • Code: improved = ev["loss"] < best → save best.pt (ext_poisson_train.py:130–133; ext_train.py:142–145).
  • Early stopping: training stops after 10 epochs without improvement (since >= args.patience, line 139 / 151). Best epochs ranged from 59 to 80; 7 of 20 models stopped early.
  • After training, the best checkpoint was reloaded and re-scored; the reload matched the logged numbers exactly (best_reload_max_abs_diff = 0.0 in every report).
  • A second, separate validation step followed: ext_poisson_evaluate.py --level … (default split = validation) scored the selected checkpoints on the same 1,000 validation images with 4 new sequences (2026–2029; 4,000 pairs) and applied the pass rule. This run then froze the checkpoints by recording their MD5 hashes in results/…/frozen_for_test.json (ext_poisson_evaluate.py:188).
  • The Gaussian-smoothing σ of the smoothed-DGI baseline was tuned on training images (tune_sigmas, line 99) and frozen with the checkpoints.

4. Testing

Yes: the frozen models were tested once on a separate test set of 2,000 images (1,000 blood + 1,000 tissue) × 4 measurement sequences = 8,000 pairs per model family.

  • The test images come from MedMNIST's official test split. For PathMNIST this split (CRC-VAL-HE-7K) comes from a different clinical centre than the training images.
  • Guards in the code (ext_poisson_evaluate.py:86–95, ext_evaluate.py:144–153): the test split is loaded only with --final-test and only if frozen_for_test.json exists; every checkpoint's MD5 must equal the frozen value; the script refuses to run if a test report already exists.
  • Result files: results/level_{p05,p10,p30}/test/ and outputs/extension_medmnist_microscopy/results/target_{clean,dgi10k}/test/ (per_image_results.csv has 2,000 test IDs × 4 seeds; comparisons.csv; evaluation_report.json).

5. What the test compared

Yes: every U-Net output and every conventional DGI image was scored against the original image.

  • Methods scored: conventional DGI-500 … DGI-10000, Gaussian-smoothed DGI-N, the U-Net (AI-original-N), and in the noise runs the noise-free DGI-10000 as context.
  • Pass rule (fixed before training): the U-Net must not be worse than DGI-10000, judged by the lower 95% bootstrap bound ≥ −0.02 SSIM and ≥ −0.01 r (ext_poisson_evaluate.py:154). The test also reports U-Net vs DGI at the same shot count.
  • NCC is reported as Pearson r (the CSV column is named correlation); there is no separate "NCC" column.

6. Separation of the three sets

Training, validation and test images are completely separate.

  • 10,000 unique image IDs; overlaps train–val 0, train–test 0, val–test 0. No two of the 10,000 images are pixel-identical, and the duplicate screen found no near-duplicate or flipped/rotated copies among them.
  • The training scripts assert that no test ID is in the training or selection data (ext_poisson_train.py:72, 78); every report records test_ids_in_training_or_selection = 0.
  • The network input is the DGI image only. The original image is used as the training target (training images) and for scoring, never as an input.
  • All test result files contain only …_test_… IDs; all validation files only …_val_… IDs.

Disclosure: before any model was trained, the evaluation code was smoke-tested on 24 test images with untrained placeholder networks to check that the script runs. Nothing from it was used for training, tuning or selection. The test set was never used for training or model selection.

8. Validation performance vs test performance

Validation numbers were used to select and freeze; test numbers are the reported results. Minimum number of shots at which the U-Net passes the pre-registered rule against DGI-10000 of the same acquisition (noisy at 5/10/30%), shown as validation → test:

1,000 shots is the minimum for all images together at every noise level; it is not the minimum for tissue alone. Tissue at 1,000 shots fails at every noise level on both validation and test (for example, test at 30%: lower bounds −0.042 SSIM and −0.068 r). It passes at 2,000 shots at 10% and 30% noise, and only at 5,000 at 0% and 5%. The earlier pass at 2,000 for tissue at 10–30% is partly because noise weakens the DGI-10000 comparator. Source: comparisons.csv and evaluation_report.json in each results/…/{val,test}/ folder; decisions re-derived independently in audit/final_verification/E_pass_fail_by_subset.csv (96 of 96 agree).

Across all 27 noise-experiment cases (all images, blood and tissue separately, three comparisons) validation and test agree in 25. The two differences are borderline 10% results (tissue against noisy DGI-10000, shown above, and all images against the noise-free DGI-10000).

The complete sequence

  1. Dataset preparation (ext_build_dataset.py): download MedMNIST+ 64 × 64 (MD5-checked), draw 3,500 / 500 / 1,000 images per collection from the official splits, screen for duplicates, convert to grey [0, 1].
  2. Protocol (ext_write_protocol.py, ext_poisson_write_protocol.py): design and pass rule written to protocol.json before any training data existed.
  3. Simulation (ext_build_pool.py, ext_poisson_build_pool.py): training pool from training images; validation (selection) set from validation images. No test image is used.
  4. Training (ext_train.py, ext_poisson_train.py): train on 7,000 images; score the 3,000 validation pairs after every epoch; keep the lowest-MSE checkpoint; early stopping.
  5. Validation evaluation and freezing (…evaluate.py without --split test): score the selected checkpoints on validation images with 4 new sequences, apply the pass rule, write MD5s to frozen_for_test.json.
  6. Single test evaluation (…evaluate.py --split test --final-test): load the 2,000 test images, verify the checkpoint MD5s, score U-Net and DGI against the original images, apply the same pass rule. Run once per model family.
  7. Freeze manifests: all results hashed (FREEZE_MANIFEST_extension.md5, 131 files; FREEZE_MANIFEST_poisson.md5, 180 files); all checks pass.
